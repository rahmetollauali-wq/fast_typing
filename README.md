# Fast Typing (tempo)

Веб-тренажёр скорости и точности печати: 6 режимов, 2 языка, 3 уровня сложности, история попыток, личные рекорды и таблица лидеров.

Оформление: темная и новогодняя темы. В новогодней — снегопад, гирлянда, шапочки, носки и подарки. Переключатель находится в шапке, выбор сохраняется в браузере.

Режим «На время» использует связные тексты, режим «Слова» — случайные слова из словаря.

**Стек:** React + Vite · Node.js + Express · PostgreSQL 16 · Docker Compose

## Запуск

```bash
cp .env.example .env        # на Windows: copy .env.example .env
docker compose up --build
```

| Что | Адрес |
| --- | --- |
| Приложение | http://localhost:5173 |
| API | http://localhost:3000/api/health |
| PostgreSQL | localhost:5432 |

Администратор создаётся автоматически при первом запуске: логин и пароль берутся из `.env` (`admin` / `admin12345`). Значок клавиатуры в шапке открывает управление текстами.

### Демо-данные для таблицы лидеров

```bash
docker compose exec backend npm run seed:demo
```

Создаёт 40 пользователей с попытками за последние 10 дней (пароль у всех: `demo12345`).

### Тексты и цитаты

`02-texts.sql` содержит словари для режимов «Слова» и «На время». `03-more-texts.sql` и `04-more-texts.sql` добавляют по 48 осмысленных текстов и цитат: вместе это по 10 классических текстов и 6 цитат для каждого языка и уровня сложности. Старые короткие тексты из базового набора заменены. На чистой базе файлы выполняются автоматически. На уже существующей базе их можно применить повторно — дубликаты не добавятся:

```bash
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -f /docker-entrypoint-initdb.d/03-more-texts.sql -f /docker-entrypoint-initdb.d/04-more-texts.sql'
```

## Дуэли

1. Игрок входит в аккаунт, открывает **Duel** в шапке, выбирает режим и нажимает **create room**.
2. Появляется временный код из 6 символов (действует 10 минут). Его можно скопировать вместе со ссылкой.
3. Соперник открывает **Duel → Join by code** и вводит код, или просто переходит по ссылке.
4. Как только в комнате двое, идёт отсчёт 3-2-1, и оба печатают один и тот же текст. Прогресс соперника виден в реальном времени.
5. В конце показывается таблица «вы против соперника» и победитель. Побеждает тот, у кого выше Quality Score; при равенстве — кто закончил раньше. Кнопка **rematch** переносит обоих в новую комнату.

Попытки из дуэли считаются по тем же правилам и попадают в историю и рекорды. Итоги дуэлей хранятся в таблице `duels`. Она создаётся автоматически при старте backend, поэтому удалять существующую базу не нужно.

Связь в реальном времени идёт по WebSocket `/api/duels/ws` через тот же порт 5173 (Vite проксирует его на backend).

## Доступ из локальной сети

Сайт уже открыт для устройств в вашей сети: Docker публикует порт 5173, а Vite слушает все адреса. Нужно сделать три вещи:

1. **Узнать IP компьютера**, на котором запущен Docker:
   - Windows: `ipconfig` → «IPv4-адрес» у Wi-Fi или Ethernet (например `192.168.1.10`);
   - macOS: `ipconfig getifaddr en0`;
   - Linux: `hostname -I`.

   Адрес из лога Vite («Network: http://172.x.x.x») — это адрес внутри контейнера, он не подходит.
2. **Разрешить входящие подключения на порт 5173:**
   - Windows: при первом запуске разрешите Docker Desktop доступ в «Частных сетях». Профиль сети должен быть «Частная» (Параметры → Сеть → Wi-Fi → Тип профиля). Или в PowerShell от администратора:
     `netsh advfirewall firewall add rule name="Fast Typing" dir=in action=allow protocol=TCP localport=5173`
   - macOS: Системные настройки → Сеть → Брандмауэр → разрешить входящие для Docker;
   - Linux с ufw: `sudo ufw allow 5173/tcp`.
3. **Друзья открывают `http://<ваш IP>:5173`**, например `http://192.168.1.10:5173`. Все устройства должны быть в одной сети.

Если не открывается: в гостевых и университетских Wi-Fi часто включена изоляция клиентов (устройства не видят друг друга). Тогда раздайте точку доступа с телефона или используйте домашний роутер.

База (5432) и backend (3000) намеренно доступны только с самого компьютера (`127.0.0.1` в `docker-compose.yml`): весь трафик из сети идёт через 5173.

## Архитектура

Три контейнера: `frontend` → `backend` → `db`. Сервер разделён на три слоя, и каждый обращается только к соседнему:

```
backend/src/
├── api/              1. Слой API: маршруты, проверка токена, единый формат ошибок
│   ├── routes/          auth, texts, attempts, leaderboard, profile, admin, meta
│   └── middleware/      optionalAuth, requireAuth, requireAdmin
├── api/duelSocket.js  WebSocket дуэлей
├── services/         2. Бизнес-логика
│   ├── duelService      комнаты, коды, отсчёт, победитель, реванш
│   ├── metrics.js       разбор журнала нажатий и расчёт WPM / точности / QS
│   ├── attemptService   проверка попытки, сохранение, обновление рекорда
│   ├── textService      выбор случайного текста, сборка слов для режимов «Слова» и «На время»
│   ├── authService      регистрация, вход, токены, bcrypt
│   ├── leaderboardService, profileService, adminService
├── repositories/     3. Доступ к данным: только здесь SQL
└── scripts/seedDemo.js

frontend/src/
├── pages/            Тест, Результат, Лидеры, Профиль, Вход, Админ
├── components/       WordsView (подсветка текста), TestSettings, LineChart, Layout
├── context/          вход пользователя, настройки теста
├── api/client.js     запросы к серверу
└── i18n/             интерфейс на английском и русском

db/init/
├── 01-schema.sql     8 таблиц по ER-диаграмме + справочники
├── 02-texts.sql      словари для «Слова» и «На время» (RU и EN, три сложности)
├── 03-more-texts.sql тексты и цитаты, набор 1 (48 строк)
└── 04-more-texts.sql тексты и цитаты, набор 2 (48 строк)
```

**Результат считает сервер.** Клиент отправляет журнал нажатий (`[{t, k}]`), сервер проигрывает его заново, проверяет, что текст действительно был выдан, и только после этого считает метрики. Результат выше 250 WPM отклоняется. Поэтому подделать результат с клиента нельзя.

## Формулы (раздел 7.1 ТЗ)

- **WPM** = (верные символы / 5) / время в минутах
- **Точность** = верные нажатия / все нажатия × 100%
- **QS** = WPM × (Точность / 100)²

Ошибка, исправленная через Backspace, всё равно снижает точность. Рекорд обновляется, только если новый QS строго больше. Таймер стартует с первого нажатия.

## API

| Метод | Путь | Описание |
| --- | --- | --- |
| POST | `/api/auth/register` | Регистрация `{login, password}` → `{user, token}` |
| POST | `/api/auth/login` | Вход → `{user, token}` |
| POST | `/api/auth/logout` | Выход (токен аннулируется) |
| GET | `/api/auth/me` | Текущий пользователь |
| GET | `/api/texts/random?mode&language&difficulty&option` | Случайный текст для теста |
| POST | `/api/attempts` | Отправить попытку: гость получает результат, пользователь — ещё и сохранение |
| GET | `/api/attempts?mode&page` | История попыток, по 20 на страницу |
| GET | `/api/profile` | Сводка, рекорды, прогресс |
| GET | `/api/leaderboard?mode&language&difficulty&period&page` | Топ-50, `period` = `today` / `week` / `all` |
| GET/POST/DELETE | `/api/admin/texts` | Управление текстами (только администратор) |
| GET | `/api/meta` | Справочники режимов, языков, сложностей |
| POST | `/api/duels` | Создать комнату дуэли → временный код |
| GET | `/api/duels/:code` | Проверить комнату по коду |
| GET | `/api/duels/history` | Статистика и последние дуэли пользователя |
| WS | `/api/duels/ws?token=…` | Комната в реальном времени: `join`, `progress`, `finish`, `rematch`, `leave` |

Токен передаётся в заголовке `Authorization: Bearer <token>` и действует 7 дней.

## Отличия от ER-диаграммы в ТЗ

- В `attempts` добавлены `raw_wpm` (колонка «Raw WPM» в таблице лидеров) и `mode_option` (длительность для «На время» или число слов для «Слов»).
- Новая таблица `duels` (итоги дуэлей: код, игроки, их попытки, победитель).
- Ограничение `CHECK` на `text_id` / `custom_text`: «не оба сразу» вместо «ровно одно». В режимах «Слова» и «На время» текст собирается из словаря, поэтому оба поля пустые.
